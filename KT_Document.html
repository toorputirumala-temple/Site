Project Overview

Purpose

This is the official temple website for Sridevi Bhoodevi Sametha Sri Prasanna Venkateswara Swamy Devasthanam, locally known as Toorpu Tirumala (Eastern Tirumala). The website serves as a digital presence for the temple, enabling devotees to:

  • Learn about the temple's history, divine deity, and management
  • View upcoming and recent events (Brahmotsavams, festivals)
  • Book the temple's Kalyana Mandapam (function hall) online
  • Make UPI-based donations directly to the temple
  • Browse the sacred photo gallery
  • Find the temple's location via an embedded Google Map

GalleryPage – Marquee Gallery Detail

The gallery uses pure CSS animation (no library) to create 3 infinite-scrolling rows:

  • Row 1 — scrolls LEFT at 35s duration
  • Row 2 — scrolls RIGHT at 42s duration (reversed image order)
  • Row 3 — scrolls LEFT at 30s duration (offset slice)

Images are duplicated ([...images, ...images]) for seamless looping. The entire .gallery-rows pauses on hover via animation-play-state: paused.

Clicking any card opens a fullscreen lightbox modal with keyboard navigation (← → Escape).

Currently, 9 static images are hardcoded in the images array inside GalleryPage.jsx. They are loaded from /public/templedata/.

⚠️
Note: Gallery images are hardcoded. Adding new photos requires editing the images array in GalleryPage.jsx and placing files in public/templedata/.

DonateSection Component

A floating golden button (fixed, bottom-right) opens a two-step donation modal:

Admin Panel

Route: /admin

The admin panel is accessible at /admin. It requires Firebase email/password authentication.

Authentication Flow

  1. User visits /admin
  2. If not logged in → shows Login form (email + password)
  3. Calls signInWithEmailAndPassword(auth, email, password)
  4. On success → shows Event Management dashboard
  5. Logout via signOut(auth)
🔐
Admin User Setup: The admin email/password must be created manually in the Firebase Console → Authentication → Users. It is not created via the website itself.

Event Management (Add New Event)

The admin can add new temple events with:

  • Event Name (e.g., "Maha Shivaratri 2026")
  • Event Date (date picker)
  • Event Details (textarea)
  • Google Drive Image Links — minimum 2 required. Links must have "Anyone with the link" sharing access. The image URL is converted to display format for rendering.

Data is written to Firestore events collection with serverTimestamp(). The EventsPage reads this collection in real-time.

Running the Project Locally

Prerequisites

  • Node.js 18+ installed
  • .env file filled with valid Firebase + SMTP credentials
  • Firebase project created and Firestore database initialized

Setup & Start

# 1. Install dependencies (root project)
npm install

# 2. Install server dependencies
cd server && npm install && cd ..

# 3. Start both Vite dev server AND Express mail server concurrently
npm run dev

# This runs: "concurrently \"vite\" \"node server/index.js\""
# Vite → http://localhost:5173
# Express → http://localhost:3001

Vite Dev Server Proxy

The vite.config.js proxies /api/* requests to the Express server:

// vite.config.js
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:3001',
      changeOrigin: true,
    }
  }
}

This means in development, fetch('/api/send-mail') in the browser is transparently forwarded to http://localhost:3001/api/send-mail.

Deployment

Vercel Deployment

The project is configured for Vercel deployment via vercel.json:

{
  "buildCommand":   "vite build",
  "outputDirectory": "dist",
  "rewrites": [
    { "source": "/api/(.*)",  "destination": "/api/$1"   },
    { "source": "/(.*)",      "destination": "/index.html" }
  ]
}
RewriteExplanation
/api/*Routes to Vercel serverless functions in the api/ folder (e.g., api/send-mail.js)
/*All other routes → index.html (enables React Router client-side routing)
⚠️
Environment Variables on Vercel: All .env variables must be added to Vercel project settings under Settings → Environment Variables. They are NOT read from the local .env file in production.

Serverless Email on Vercel

The file api/send-mail.js is the Vercel serverless equivalent of the Express server. In production, Mandap booking email requests go to this serverless function instead of the local Express server.

Architecture Decisions

  • Single-page scroll layout — All sections on /, navigated via smooth scroll anchors. No multi-page routing for public sections.
  • Firebase Firestore (NoSQL) — Chosen for real-time data, easy admin-side event publishing, and zero backend infrastructure needed for reads.
  • Pure CSS animations — Gallery marquee and most animations use CSS @keyframes without GSAP, for lightweight performance.
  • Tailwind CSS — Utility classes for rapid layout; custom animations are in App.css and inline <style> tags for component-scoped CSS.
  • Google Drive image links — Events gallery uses Google Drive shareable links (converted to direct CDN URLs) to avoid Firebase Storage costs.
  • Device-aware donation UX — QR code on desktop, deep-links on mobile, for the best UPI payment experience on each platform.
  • Bilingual architecture — All strings in one central file enables easy translation updates and Telugu language support without code changes.
